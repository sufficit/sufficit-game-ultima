# LFM2.5 CPU option

## Investigation

LFM2.5-350M returned native tool calls with wllama 3.13.0 in previous
experiments. The game needed a model selection that loaded the same
pinned Q4_K_M file through the normal CPU menu.

## Changes

Added the 229,312,224-byte Liquid AI GGUF as an experimental CPU option.
Selecting a model stores the preference and leaves the activation control
available. The selector stays unavailable while generation is active.
Qwen remains the default.

The browser matrix selects LFM through the game menu and substitutes only
the verified download URLs. It confirms the selected model key before
running real inference. The garden fixture includes two flower beds.

## Validation and delivery

The Release publish, RulesSmoke, 14 JavaScript tests and the browser
preference persistence test passed. Chromium with SwiftShader loaded the
pinned LFM model and exercised the five Portuguese turn cases through the
Guardian dialogue, current tool schema and disposable garden API.

| Case | Result |
| --- | --- |
| Raise both lanterns by 1 m | Applied to both after confirmation in the game. The first reply took 11.49 s. |
| Reduce height by 30 cm | Sent an absolute set operation with a string value of -30. The game rejected the proposal. |
| Set the flower color | Sent an add operation for a hexadecimal color. The game rejected the proposal. |
| Repeat the color on the other flowers | Proposed a landscape plan involving a lantern. The proposal was left unconfirmed. |
| Negation | Returned a reply without a tool call. |

The model matched two cases and did not qualify as the default. All
unconfirmed turns preserved the map revision. Only the confirmed
one-metre increase modified the world.
