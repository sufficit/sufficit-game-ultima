# Keyboard movement and camera look

## Investigation

The shared input mapper treated arrow keys as aliases for WASD.
The front third-person camera also held its horizontal angle relative
to the avatar when the player tried to orbit.

## Changes

- [PlayerInput](../../engine/Ultima.Terrain/PlayerInput.cs) maps WASD to
  translation and the arrow keys to the existing look axes. Movement and
  camera control can run simultaneously within the same input frame.
- Both environments use the look axes to turn and tilt the camera.
  The front third-person camera starts facing the avatar and uses the
  look input to orbit from that heading.
- Updated keyboard hints in both environments and the player guides.

## Validation and delivery

- The terrain WebAssembly build, Release publish and RulesSmoke passed.
- The `camera-views` and `input-devices` scenarios passed locally in
  Chromium with SwiftShader, with the garden running in worker and
  main-thread modes. The camera scenario verified horizontal and vertical
  look without player displacement in all three views in both environments.
- The `camera-views` scenario passed again on the published revision
  `dc02f7469d88b1d1bf84ac161b051d091dd9365d` in both modes.
