# Authored NPC dialogue topics

## Investigation

The Guardian and Wanderer already used the same C# dialogue brain and scheduler.
The conversation window supported opening lines, free text, and external
replies. The existing state machine could also handle authored topics by ID.

## Changes

- The [topic catalog](../../src/Npc/DialogTopics.cs) provides three Guardian
  topics and two Wanderer topics. The C# brain accepts selections for the
  active speaker, adds the question and answer to the visible transcript,
  and offers the topics again. Pending free-text replies suspend selections.
- The existing declarative window renders topics with the conversation's
  outlined Sufficit.Blazor.UI buttons and wrapping layout. This follows the
  project design and reuses the controls already used for garden actions.
- [Index.Dialogue.cs](../../src/Pages/Index.Dialogue.cs) holds the dialogue
  integration in a C# partial class. The [guide](../USAGE-DIALOGUE.md)
  describes how to add a topic and where its turns are displayed.
- [AGENTS.md](../../AGENTS.md) records the English documentation and comment
  convention, conversion of completed plans, C# migration preference, and
  the 400-line source-file target.

## Validation and delivery

- Release publish and RulesSmoke passed. RulesSmoke covered all five topic
  paths, unknown IDs, closed sessions, and pending free-text replies.
- The Chromium declarative window scenario passed locally and on GitHub
  Pages in both rendering modes. It verified topic selection by keyboard
  and pointer before enabling AI, transcript updates, and the existing
  conversation, narration, and Journal paths with simulated AI responses.
- Mobile layout passed in portrait and landscape and at desktop and tablet
  sizes. A 390×844 screenshot confirmed that topic buttons wrap within the
  existing conversation panel.
